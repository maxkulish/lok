## Verdict: **APPROVE_WITH_SUGGESTIONS**

## Summary

This is a strong, unusually well-scoped design. It correctly treats the current markdown snippets as production gate logic, gives the replacement a clear executable contract, makes failure modes explicit, and backs the change with a genuinely meaningful test matrix. The architecture is sound: one POSIX shell dispatcher, strict input validation, no shared shell state, a single owner of reviewer-identity matching, and a CI job that both lints and executes the gates.

The main issues are narrow and fixable:

1. The fake `gh` contract does not currently support the `unresolved-threads` GraphQL call.
2. The design does not specify a per-request timeout for `gh api`, only a poll-loop deadline.
3. A few consistency and portability details should be tightened before implementation.

## Key strengths

- **Fail-closed semantics are first-class.** Exit codes 1–4 are clearly separated, and "only exit 0 may be recorded as a passed gate" is exactly the right rule.
- **State ownership is clean.** Moving from caller shell variables to argument-only subcommands removes the current "all blocks must run in one shell" fragility.
- **The test plan is excellent.** It covers the two known PR #71 defects, stale passes, empty bounds, malformed timestamps, head changes, billing-blocked behavior, and shell portability.
- **CI integration is well thought out.** Adding the job to both `needs` and the `ci-gate` assertion loop is the right move; merely adding it to `needs` would indeed not fail the gate.
- **Non-goals are unusually clear.** Keeping CLO-650 separate and leaving the `phases/pr.md` §5.0 gate out prevents this task from becoming a semantic rewrite.
- **Security posture is good.** No secrets are introduced, inputs are validated, and the fake `gh` is path-scoped to tests.

## Findings

### 1. P1 — Fake `gh` does not support the GraphQL shape needed by `unresolved-threads`

The fake `gh` is specified to accept only: `api <path>`, `--paginate`, `--slurp`, `-X POST`, `-f body=<text>`. But `unresolved-threads` needs a GraphQL call with `-f query=<text>`, a `graphql` endpoint, and explicit handling of the GraphQL `errors` envelope.

**Action:** Add `-f query=<text>` and the `graphql` path to the fake `gh` allowlist and fixture resolver.

### 2. P1 — Add a per-request timeout for `gh api`

The design specifies `--timeout` for the poll loop, but not a timeout for each `gh api` call. A hung `gh` process can block the gate indefinitely, even though the poll deadline has passed.

**Action:** Either rely on an explicit `gh` timeout option and document it, or add a script-level per-request timeout seam (e.g., `PR_REVIEW_CYCLE_REQUEST_TIMEOUT`) and test a hung request.

### 3. P2 — Subcommand count is inconsistent between Goals and the actual API

The Goals section says "five subcommands," but the design later adds `unresolved-threads` as a sixth.

**Action:** Update the goal to explicitly list all six subcommands.

### 4. P2 — The CI grep guard needs a precise, tested pattern list

The current description risks false positives. The guard should be treated as code, not prose.

**Action:** Specify the exact regexes, file scope, anchoring rules, allowlist encoding, and a self-test proving the guard fails on each banned shape and passes on each allowlisted one.

### 5. P2 — Make POSIX shell discipline explicit

The design should state the exact portability rules: no `local`, `[[]]`, `pipefail`, bash-only parameter expansion, or GNU-only flags; `set -u` is acceptable; `set -e` is risky with intentional non-zero exits.

**Action:** Document these constraints to prevent bashism drift during implementation.

### 6. P2 — Specify GraphQL error handling explicitly

The test plan says `unresolved-threads` fails closed on GraphQL errors, but the architecture does not detail how.

**Action:** Add an explicit rule covering non-zero exits, non-empty `errors` array, missing/null `data` fields, and malformed thread objects — all exit 3.

### 7. P3 — Timestamp validation may be too strict

`require_iso8601z` accepts only exact second-resolution. Some GitHub endpoints include fractional seconds.

**Action:** Either document that all endpoints used emit the exact shape, or broaden the validator to accept optional fractional seconds with trailing `Z`.

### 8. P3 — Ensure JSON output is generated by `jq`, not string interpolation

`new-comments` and `unresolved-threads` print JSON with user-controlled fields that can contain quotes, newlines, backslashes, and Unicode.

**Action:** State explicitly that output objects are built with `jq -c`, not shell interpolation.

### 9. P3 — Add a few more edge-case tests

The test plan is already strong. Three additions would improve confidence:
- `unresolved-threads` with multiple threads and pagination.
- `new-comments` when `created_at` exactly equals `--since`.
- `wait-rereview` when head changes between lookup and first poll.

## Prioritized action items

1. Fix the fake `gh` contract to support GraphQL.
2. Add a per-`gh`-request timeout and test a hung request.
3. Update goal/API count to include all six subcommands.
4. Make CI guard regexes exact and self-tested.
5. State POSIX shell portability rules explicitly.
6. Add explicit GraphQL error-handling rules.
7. Clarify accepted ISO-8601 variants.
8. Require `jq -c` for JSON output generation.
9. Add the three extra boundary tests.

With items 1 and 2 addressed, this design is ready for implementation.
