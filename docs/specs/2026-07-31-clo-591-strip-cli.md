# Spec: Strip CLI presentation from the library surface

**Created**: 2026-07-31
**Revised**: 2026-07-31 (rev 2, after external review; every point validated against the code)
**Linear**: [CLO-591](https://linear.app/cloud-ai/issue/CLO-591)
**Estimated scope**: L (~18 files, 10 sub-tasks). Raised from M: the public-API and rustdoc work alone is 101 items.
**Approach**: narrow. Single package, feature-gated binary dependencies. The workspace split was considered and declined; see Decision D1.

## 1. Problem Statement

`lokomotiv` gained a `[lib]` target in CLO-593 (PR #61, merged `ee28f3c`). The split moved most terminal rendering to the binary side, but a consumer depending on the library still inherits CLI behavior, CLI dependencies, and an undocumented public surface.

### Terminal writes on consumer-reachable paths

| Site | Stream | What it writes |
| --- | --- | --- |
| `src/backend/retry.rs:102` | stderr | `  ↻ Retrying {name} (attempt {n}/{max}) in {delay:?}...`, glyph colored via `colored` |
| `src/backend/mod.rs:440` (`resolve_health_cache_ttl`) | stderr | `warning: {msg}` on a bad `LOK_HEALTH_TTL`, prefix colored via `colored` |
| `src/backend/codex.rs:147` and `src/backend/gemini.rs:505` (`resolve_effective_sandbox`) | **stdout** | `[WARN] apply_edits=true but sandbox is read-only; ...` |
| `src/backend/claude.rs:445`, `:449`, `:464` | stderr | Unconditional `claude --version` probe diagnostics |

The Linear issue named only `retry.rs`. The `mod.rs` site, and the two `println!` sites writing to **stdout** (worse than stderr, since it corrupts a consumer's piped output), were found during verification and are in scope.

### CLI dependencies on a library consumer's tree

`indicatif` and `colored` are unconditional `[dependencies]` (`Cargo.toml:48-49`). Cargo resolves dependencies per package, not per target, so a consumer building only the `lib` target still compiles them.

Verified unused inside `src/backend/`: `indicatif` (0 references), `clap` (0), `chrono` (0), `dirs` (0), `futures` (0), `minijinja` (0), `sha2` (0). `colored` has exactly 2. `indicatif` code is confined to `src/engine.rs:14,270,282`, which is binary-only: `src/lib.rs` declares only `pub mod backend;`, while the 19 orchestration modules are declared in `src/main.rs:1-19`.

### An undocumented, oversized public surface

`RUSTDOCFLAGS='-D missing_docs' cargo doc --no-deps --lib` currently reports **101 missing-documentation errors**. `src/backend/` exports ~90 `pub` items across 9 files, weighted to `mod.rs` (44), `context.rs` (14) and `bedrock.rs` (9). Provider internals are reachable that no consumer needs: `ClaudeMode`, `FlagRequirement` and the Bedrock wire DTOs all have **zero** references outside `src/backend/`.

The `test-support` feature leaks Tokio into consumer signatures in two places, not one: `acquire_test_lock` returns `tokio::sync::MutexGuard<'static, ()>` (`src/backend/mod.rs:506`), and `TEST_MUTEX` is itself `pub static tokio::sync::Mutex<()>` (`src/backend/mod.rs:503`). Wrapping only the guard would leave the leak open through the static.

### No enforcement

`.github/workflows/ci.yml:33-37` runs `cargo build` and `cargo test` with default features only. Since `cli` will be a default feature, a future `colored` import on a library path would compile and ship green.

`docs/adrs/clo-589-backend-library-shape.md:156-167` records six divergences from the ADR's allocation table, all still open, and two of the six are factually wrong (see the resolution table).

**Why it matters:** CLO-592 publishes this to crates.io. Whatever surface, dependency set and documentation exist at that point become a public contract that is expensive to retract.

## 2. Acceptance Criteria

- [ ] **AC1** A consumer depending on the library with `default-features = false` gets none of these **exact packages** in `cargo tree`: `indicatif`, `colored`, `clap`, `chrono`, `dirs`, `futures`, `minijinja`, `sha2`. Matching is by exact package name, not substring; see Constraints for why.
- [ ] **AC2** The library performs **no direct terminal writes**. Specifically: (a) with no logger installed, a consumer sees zero bytes on stdout and stderr across a successful query, a retry, and a read-only-sandbox call; (b) `src/backend/` contains no `println!`, `eprintln!`, `print!` or `eprint!`, enforced by a grep gate; (c) with a logger installed, the consumer receives those messages as `log` records.
- [ ] **AC3** No library path can reach `colored` or `indicatif`. Enforced by both being optional and absent from the non-`cli` feature set, plus a CI job that builds the library with `--no-default-features`.
- [ ] **AC4** Every `pub` item reachable from `lokomotiv::` is classified in the ADR into exactly one of **four** categories: *abstraction*, *binary-support*, *test-only*, *removed*. The fourth category, binary-support, is new and is justified in D4.
- [ ] **AC5** `RUSTDOCFLAGS='-D missing_docs' cargo doc --no-deps --lib` exits 0, as a **permanent** gate in CI, not a temporary lint. Current baseline: 101 errors.
- [ ] **AC6** The `test-support` feature exposes no `tokio` type in any public signature. Both `acquire_test_lock`'s return type and `TEST_MUTEX` are covered.
- [ ] **AC7** All three CLO-593 ADR follow-ups are resolved or deferred with a written reason.
- [ ] **AC8** `docs/adrs/clo-589-backend-library-shape.md` has no open divergence rows, and the two factually incorrect rows are corrected.
- [ ] **AC9** `StepContext` is confirmed call-shaped, recorded in the ADR and the PR body.
- [ ] **AC10** A real `cargo install --path . --root <tmp>` produces both `lok` and `lokomotiv` executables with no extra flags, and a bare `cargo build` produces both.
- [ ] **AC11** `lok` still shows retry and TTL warnings on stderr by default, with no logger chrome: no timestamps, no target names, no `WARN` level headers. Verified against a **deterministic** message, not a jittered one.
- [ ] **AC12** Green under both feature configurations, as permanent CI jobs:
  - default: `cargo test --all-targets`, `cargo clippy --all-targets -- -D warnings`
  - lean: `cargo test --lib --no-default-features`, `cargo clippy --lib --tests --no-default-features -- -D warnings`
  - bedrock: `cargo check --no-default-features --features bedrock`
  Zero failures, zero ignored. The lean configuration deliberately excludes `--all-targets`; see Constraints.
- [ ] **AC13** The Linear issue's acceptance criterion 1 is **amended in Linear** before implementation starts, not merely noted in the PR body.

## 3. Constraints

**Must**:
- Keep `default = ["cli"]` so `cargo install lokomotiv` is unaffected (AC10).
- Add `required-features = ["cli"]` to both `[[bin]]` targets so `--no-default-features` skips them rather than failing to compile.
- Route every library warning through the `log` facade. `log::warn!` with no logger installed is a no-op, which is what makes AC2(a) hold.
- **Shrink the public surface before documenting it.** Demoting an item that nothing outside `src/backend/` uses is cheaper than writing rustdoc for it. Do sub-task 6 before sub-task 7.
- **Match dependency names exactly** in the AC1 check. A substring match on `futures` produces a false positive: `futures-core`, `futures-util`, `futures-channel`, `futures-task`, `futures-sink` and `futures-io` remain in the tree via `reqwest -> hyper-tls -> hyper-util -> futures-util`, and `reqwest` is a genuine library dependency (8 references in `src/backend/`). Only the `futures` **facade** crate is removable. Verified: `sha2` and `dirs` are direct-only and gate cleanly, `dirs-sys` leaving with `dirs`.
- Treat the two `println!` sandbox warnings as in scope even though the Linear issue omits them.
- The binary's logger must use a **custom formatter**. A bare `env_logger::init()` prepends timestamps, targets and level headers, which would visibly regress every warning line.

**Must-not**:
- Do not split the package into a workspace. Declined by the user; see D1.
- Do not change `create_backend`'s signature, or move `BACKEND_CACHE` to the binary. Both are blocked; see D2.
- Do not run `cargo test --all-targets --no-default-features` as the lean gate. `tests/integration.rs:8-12` shells out to `cargo run --bin lok`, which re-enters Cargo with default features; the result is slow and proves nothing about the lean build. Gate the lean configuration on `--lib` plus the library-only integration tests instead.
- Do not make `toml`, `which`, `regex`, `rand`, `humantime`, `tempfile`, `reqwest`, `secrecy`, `thiserror`, `anyhow`, `serde*`, `tokio` or `async-trait` optional. All are verified in use inside `src/backend/`.
- Do not emit terminal-shaped strings through `log`. The retry message's leading spaces and `↻` glyph are presentation; the library logs the facts (backend name, attempt, max, delay) and the binary renders the glyph.
- Do not add `tracing`.

**Prefer**:
- `log::debug!` over `log::warn!` for the `claude.rs` probe diagnostics; they are developer diagnostics, not user-actionable warnings.
- Deleting or demoting a `pub` item over documenting it, when nothing outside the library uses it.

**Escalate when**:
- Demoting an item to `pub(crate)` breaks the binary. This is a real hazard: the binary is a **separate crate target**, so `pub(crate)` hides an item from it. Check `src/engine.rs` and `src/workflow.rs` before every demotion.
- Feature-gating a dependency breaks a binary module in a way that needs more than a `#[cfg(feature = "cli")]` on an import.
- The lean build reveals a library dependency this spec assumed was binary-only.

## 4. Decomposition

1. **Route library warnings through `log`** - Add `log = "0.4"` as a non-optional dependency. Replace `retry.rs:102` and `mod.rs:440` with `log::warn!` (dropping `colored`, and dropping the glyph and leading whitespace from the message); `codex.rs:147` and `gemini.rs:505` `println!` with `log::warn!`; `claude.rs:445,449,464` with `log::debug!`. Remove both `use colored::Colorize;` from the library. Files: `src/backend/retry.rs`, `src/backend/mod.rs`, `src/backend/codex.rs`, `src/backend/gemini.rs`, `src/backend/claude.rs`.

2. **Add the no-terminal-writes gate** - A test or CI step asserting `src/backend/` contains no `println!`, `eprintln!`, `print!`, `eprint!` (AC2b). Cheap, and it is what stops regression. Files: `.github/workflows/ci.yml` or `tests/`.

3. **Feature-gate binary-only dependencies** - Mark `indicatif`, `colored`, `clap`, `chrono`, `dirs`, `futures`, `minijinja`, `sha2` as `optional = true`; add `cli = ["dep:indicatif", ...]`; keep `default = ["cli"]`; add `required-features = ["cli"]` to both bins. Files: `Cargo.toml`. **Blocked by sub-task 1** (`colored` cannot be optional while the library calls it).

4. **Install a binary-side logger** - Add `env_logger` under the `cli` feature. Initialize it in `main` **before any library call**, with:
   - an explicit default level of `warn`, so a custom builder does not accidentally silence warnings;
   - a filter scoped to the `lokomotiv` target, so enabling logging does not dump `reqwest`, `hyper`, AWS or Tokio records on the user;
   - a custom formatter emitting the bare message with no timestamp, target or level header, re-applying `colored` for the `warning:` prefix and the retry glyph;
   - `--verbose` raising the level to `debug`, which is what surfaces the `claude.rs` diagnostics (they are unconditional today, so this is a deliberate behavior change and belongs in the PR body).

   Files: `src/main.rs`, `Cargo.toml`.

5. **Close the Tokio leak in `test-support`** - Introduce an opaque `TestLockGuard` newtype wrapping the Tokio guard, **and make `TEST_MUTEX` private** (`src/backend/mod.rs:503`); a `pub static tokio::sync::Mutex<()>` leaks the type just as the guard did. Resolves ADR follow-up 3 and AC6. Files: `src/backend/mod.rs`, plus test call sites.

6. **Shrink the public surface** - Demote everything nothing outside `src/backend/` uses. Confirmed candidates: `ClaudeMode`, `FlagRequirement`, the Bedrock wire DTOs (`src/backend/bedrock.rs`, 9 `pub` items), `resolve_health_cache_ttl`.

   **`pub(crate)` does not cross the lib/bin boundary**, so verify each demotion against the binary first. These look internal but are consumed by `src/engine.rs` and `src/workflow.rs` and must stay `pub`:

   | Item | Consumed by |
   | --- | --- |
   | `get_backend_cache` | `src/engine.rs:97,157,458,1193` |
   | `CachedBackend` | `src/engine.rs:163`, `src/workflow.rs:7071` |
   | `is_cache_entry_fresh` | `src/engine.rs:101,187,200,464` |
   | `health_cache_ttl` | `src/engine.rs:83,99,182,197` |
   | `parse_health_cache_ttl` | `src/engine.rs:1871+` |
   | `HEALTH_TTL_LOGGED` | `src/engine.rs:80` |

   Files: `src/backend/*.rs`, `src/lib.rs`.

7. **Document the remainder and gate it** - Add `#![warn(missing_docs)]` to `src/lib.rs`, document every surviving public item, and add the permanent `RUSTDOCFLAGS='-D missing_docs' cargo doc --no-deps --lib` CI job (AC5). Baseline 101 errors; sub-task 6 should cut this materially before any prose is written. Also re-export `ClaudeBackend` at the crate root for parity with its siblings, and keep `FLAG_MATRIX` at `backend::codex::FLAG_MATRIX` (the binary uses it) with documentation. Files: `src/lib.rs`, `src/backend/*.rs`. **Blocked by sub-task 6.**

8. **Build the silence test harness** - The naive design does not work: `resolve_effective_sandbox` is **private** in both providers (`src/backend/codex.rs:140`, `src/backend/gemini.rs:498`) so no integration test can call it; `tests/backend_public_api.rs:116,120` deliberately `eprintln!` skip messages when Ollama is absent; and `cargo test 2>err.txt` captures Cargo's and the harness's own output, not just the library's.

   Build instead a **helper binary** (a `[[bin]]` with `required-features = ["test-support"]`, or an example) that the test spawns and whose streams it captures. It must:
   - drive retries through a deterministic mock `Backend` returning a retryable error, with `retry_delay_ms` set to 0 so the suite stays fast and needs no closed port;
   - reach the sandbox warning through the **public** `query()` path using fake `codex`/`gemini` executables (reuse `write_exec_script`, `src/backend/mod.rs:518`), since the function itself is unreachable;
   - be invoked in two modes, no-logger and logger-installed, asserting zero bytes in the first and the expected records in the second (AC2a, AC2c);
   - require no live Ollama.

   Capture only the child's streams. Files: new helper bin, `tests/backend_public_api.rs`, `Cargo.toml`.

9. **Add the CI gates** - `.github/workflows/ci.yml` currently runs default features only (`:33-37`). Add permanent jobs for the lean build, lean clippy, the bedrock check, the dependency-tree assertion and the rustdoc gate, per AC12 and AC5. Without these, the boundary this ticket establishes is unenforced the day after it merges. Files: `.github/workflows/ci.yml`.

10. **Reconcile the ADR and Linear** - Close all six divergence rows, correct the two wrong ones, record the D2 cache deferral, record the StepContext finding, and add the four-category classification table (AC4). Separately, amend acceptance criterion 1 on the Linear issue (AC13). Files: `docs/adrs/clo-589-backend-library-shape.md`, Linear.

**Dependency order**: 1 -> 3 (colored must leave before it can be optional). 1 -> 4 (so warnings are never invisible on main). 1 -> 8. 6 -> 7 (shrink before documenting). 2, 5, 9, 10 are independent. Sub-task 9 should land last so the gates guard finished work.

## Decisions

### D1: single package with feature gating, not a workspace split

**Chosen**: `default = ["cli"]`, consumers opt out with `default-features = false`.

The alternative was splitting into `lokomotiv-core` (lib) plus `lokomotiv` (bins), which would satisfy the original criterion verbatim, keep `cargo install` working, and make the boundary a compile error rather than a convention. Declined by the user to keep CLO-591 tight.

**Consequences accepted**:
- The Linear criterion "with **default** features shows no `indicatif`" cannot hold literally, because `default = []` would break `cargo install lokomotiv` and bare `cargo build`. Amended to `default-features = false` (AC1). An ordinary consumer who does nothing still inherits every CLI dependency, which is a genuine weakening of the ticket's intent and must be amended **in Linear** before implementation (AC13), not just noted in the PR.
- The boundary stays convention-based. Sub-task 9's CI gates are the compensating control, and they are not optional: without them a future `colored` import on a library path compiles green under default features. Revisit the split before or during CLO-592.

### D2: global cache semantics deferred, with reason

**Chosen**: document the constraint; do not fix it here.

The issue offers three fixes. Verification shows the first two are **blocked by a constraint the issue did not account for**. `CachedBackend` (`src/backend/mod.rs:346`) deliberately fuses the backend instance with its health status; its doc comment says it "Replaces separate CONSTRUCTED_BACKENDS and HEALTH_CACHE maps, ensuring consistency." `is_backend_available(name)` (`src/backend/mod.rs:457`) looks entries up **by name alone**, called from the providers' own `is_available()` implementations inside the library.

So keying by `name + hash(config)` breaks that lookup, which has no config to hash, and moving the cache to the binary breaks the library's own `is_available()`. Either needs `is_available` rearchitected, which is out of scope. Document on `BACKEND_CACHE` and `create_backend`, record in the ADR, raise a follow-up against CLO-592.

### D3: `log` facade, and what it does and does not buy

**Chosen**: `log::warn!` and `log::debug!`.

`log` makes the library silent **when no logger is installed**, which is the common embedding case and what AC2(a) tests. It does **not** make the library unconditionally silent: an application that installs a logger will receive these records, by design.

That is why AC2 is phrased as "no direct terminal writes" plus a no-logger silence test, rather than "the library never produces output". It is also why the messages must stop being terminal-shaped (see Constraints): a consumer's structured logger should not receive a string with leading whitespace and a `↻` glyph in it. The library logs facts; the binary renders them.

Rejected `tracing` as more machinery than these sites justify, and rejected returning warnings as structured data as signature churn the facade already covers.

### D4: a fourth classification category

AC4 in the original draft allowed only *abstraction*, *test-only* or *removed*. That set cannot describe the health-cache items: `get_backend_cache`, `CachedBackend`, `is_cache_entry_fresh`, `health_cache_ttl`, `parse_health_cache_ttl` and `HEALTH_TTL_LOGGED` are none of the three. They are not part of the provider-agnostic abstraction, they are not test-only, and they cannot be removed because `src/engine.rs` and `src/workflow.rs` consume them across the lib/bin target boundary, where `pub(crate)` does not reach.

Adding *binary-support* is the honest description. Genuinely eliminating the category means moving the health cache into the binary, which D2 rules out of scope. The ADR records the category, its members, and that it exists because of D2.

## StepContext finding (AC9)

Confirmed **call-shaped**, not workflow-shaped. Every field on `src/backend/context.rs:12-32` is a per-call concern: `prompt`, `history`, `model`, `cwd`, `sandbox`, `apply_edits`, `schema`, `options`, `timeout`. None names a step, workflow, run or orchestration state. The struct is `Copy` with all borrows tied to the caller's frame. `StepContext::from_prompt` (`:41`) is already the narrow entry point the CLO-593 handoff asked for.

The only workflow residue is the name and the `Step`-prefixed FR comments. Recommend recording this and **not** renaming: a rename is a breaking change to the main library type for cosmetic gain, and CLO-592 is where to decide it if it matters.
