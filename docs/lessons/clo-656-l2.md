# WorkflowError variants must stay under 128 bytes or clippy fails the build

`clippy::result_large_err` fires when the `Err` type is 128 bytes or larger, and it
reports on every function returning `Result<_, WorkflowError>`, so one oversized
variant fails `-D warnings` at every call site. On 64-bit targets, each `String`
and `Option<String>` costs 24 bytes, a `&'static str` 16, and an `Option<usize>` 16.
A variant with `workflow`, `step` and two more owned strings plus two options is
already over the limit.

Rule: size a new `WorkflowError` variant when writing its spec, not after the first
clippy run. Use `&'static str` for values drawn from a fixed set (field names,
kinds), and narrow or box optional payloads before adding a fifth owned string.

How to apply: add up field sizes in the spec's variant definition. If the total
reaches 128, pick the narrower types there, so the spec and the implementation agree.
