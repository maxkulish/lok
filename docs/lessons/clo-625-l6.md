# Piping a gate command into `tail` replaces the exit status you are testing

While waiting on `CI Gate` during CLO-625, this ran:

```bash
timeout 1200 gh pr checks 74 --watch --fail-fast --interval 30 | tail -6 \
  && echo "CI_PASSED" || echo "CI_NOT_PASSED"
```

A network reset killed `gh` mid-watch. It printed `CI_PASSED` anyway.

A pipeline's exit status is its **last** command's, so the `&&` tested `tail`, which had succeeded
at printing the partial output. The gate reported green on a command that had died. Adding `| tail`
to shorten noisy output is a habit that silently disarms every gate it touches.

Capture the status before it can be laundered:

```bash
timeout 1200 gh pr checks 74 --watch --fail-fast --interval 30 >/tmp/ck.txt 2>&1
RC=$?
tail -6 /tmp/ck.txt
[ $RC -eq 0 ] || exit 1
```

`set -o pipefail` fixes the general case in bash and zsh, but it is not on by default in either, and
snippets pasted into a fresh shell will not have it.
