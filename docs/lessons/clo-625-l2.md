# Do not add a `paths:` filter to ci.yml while `CI Gate` is a required check

`main` is protected by ruleset 20153405: `enforcement=active`, `required_status_checks: ["CI Gate"]`,
**zero** `bypass_actors`. Nobody, including the repository owner, can push to `main`; everything
arrives by PR.

`ci.yml` has no `paths:` filter, so even a docs-only PR runs the full Rust matrix. That looks like
waste and invites an "optimization" that would break the repository: a required check which is
filtered out never reports at all, and a required check that never reports blocks its PR
**permanently** rather than letting it through. The absence of the filter is what makes docs-only
PRs mergeable.

If the cost ever needs addressing, the answer is a separate always-passing `CI Gate` job for
doc-only paths, never a filter on the required one.
