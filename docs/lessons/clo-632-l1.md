# lok never reads `.lok/lok.toml`; config comes from `~/.config/lok/lok.toml` and `./lok.toml` only

The setup guide's Directory Structure section tells users lok discovers
`.lok/lok.toml` at the project root. No code path opens that file. Several consumer
repositories keep their backend args and model pins there, and none of it takes
effect unless they pass `--config .lok/lok.toml`. Without a flag, they run on the
built-in defaults plus whatever `./lok.toml` and the user config hold.

Rule: before reasoning about what config a lok invocation sees, check the three real
layers (built-in defaults, `~/.config/lok/lok.toml`, `./lok.toml` in the cwd, with no
parent search), or `--config`, which replaces both files. Do not trust the guide's
directory diagram, and do not assume a consumer repo's `.lok/lok.toml` is live.

How to apply: if a task starts reading `.lok/lok.toml`, that file is project-controlled
and must go through `merge_project_file` (src/config.rs:624), or it reopens the
CLO-632 hole. Turning it on also changes behaviour for every consumer repo whose dead
config suddenly loads, and some of those files set args the gate rejects.
