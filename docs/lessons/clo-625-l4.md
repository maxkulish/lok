# Snippets marked ```bash still run under zsh, which does not word-split

Collecting several paths into one variable and expanding it unquoted is the reflexive way to build
an argument list:

```bash
PATHS="$PATHS $p"
git add -- $PATHS      # bash: three arguments. zsh: ONE argument.
```

Bash performs word splitting on unquoted parameter expansion; zsh does not, unless `SH_WORD_SPLIT`
is set. The whole string arrives as a single pathspec and the command fails on every input.

The ```bash fence on a snippet in a command file describes the dialect it was written in, not the
shell it will execute in. Here the user's shell and the agent harness are both zsh, so zsh is the
one that matters.

Avoid the dependency rather than picking a side: loop and quote each item, or use a bash array if
bash is genuinely guaranteed. Test harnesses for these snippets should run under **zsh**, since it
is the stricter of the two - what passes there passes in bash, and the reverse is not true.
