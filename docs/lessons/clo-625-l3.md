# `git add a b c` stages nothing when any one pathspec is missing

Not "stages the ones that exist". A single unmatched pathspec makes git abort with exit 128 having
staged **nothing at all**:

```
fatal: pathspec 'docs/ROADMAP.md' did not match any files
```

The damage is in what usually follows. `git add <paths>` then `git diff --cached --quiet` reads as
"no changes", so a script concludes the files are already current and skips its commit, its PR, or
its whole reason for running - while reporting success. In CLO-625 that combination would have
skipped the finalize PR and still marked the task Done.

Stage one quoted path at a time and track whether anything was found:

```bash
FOUND=0; STAGE_ERR=0
for p in a b c; do
    [ -e "$p" ] || continue
    FOUND=1
    git add -- "$p" || STAGE_ERR=1
done
```

Then treat "nothing found" and "staging failed" as distinct from "nothing changed". Only the last
is a legitimate no-op.
