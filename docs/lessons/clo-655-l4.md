# File a follow-up at the moment an out-of-scope fix is dropped

The CLO-373 branch disabled MiniJinja comment syntax as an unticketed side
change in May 2026. Both validators correctly called it out of scope and asked
for a separate PR, so it was removed. No ticket or backlog row was created. The
defect it fixed then broke CLO-653's design review in August, and it cost two
more tickets and a bisect to rediscover.

Rule: removing a real fix because it is out of scope creates a follow-up in the
same change. Record it as a Linear issue, or as a `docs/PROJECT.md` Up Next row
while Linear is capped, naming the defect and linking the review finding.

How to apply: when a validation synthesis says "split into a separate PR or
drop", the fix iteration is not complete until that follow-up exists.
