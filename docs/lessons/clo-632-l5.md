# A "command never ran" test needs a positive control and a sealed environment

A test asserting that a marker file is absent passes just as well when the hostile
script is broken, uses the wrong path, or never had a chance to run. The first
CLO-632 draft also inherited `PATH` and left the other backends enabled. If the gate
had broken, warmup would have spawned the real `claude` and `opencode` binaries,
which cost money.

Rule: pair every absence assertion with a control run that is expected to execute the
same payload. For lok config, that is the same file passed via `--config`, which is
trusted. Seal the run: `current_dir` set to the temp dir, `env_clear()`, `HOME` set to
an empty temp dir, `PATH` set to the temp dir, every unrelated backend
`enabled = false`, and a script that uses a shell redirect instead of `touch`
because `PATH` has no tools.

How to apply: watch the test fail with the gate disabled once, for example by
temporarily wiring the call site back to the ungated merge. For manual checks with a
temp `HOME`, build first and run `./target/debug/lok`. `HOME=$(mktemp -d) cargo run`
breaks rustup's toolchain lookup.
