# Pass the spec-review workflow a sanitized ticket summary, not the Linear description

The spec-review Ollama leg builds its prompt with
`sed -e 's|__LINEAR_DESC__|{{ arg.4 }}|g'`. Its input breaks on a single quote (CLO-649),
and the same construction also breaks on `|` (the sed delimiter), `&` (the matched
text), backslashes and newlines. Linear descriptions contain all of these. CLO-660 passed
a one-paragraph summary with none of those characters, and both review rounds produced
full Ollama reviews.

A summary also keeps a ticket's disproven premise out of the reviewer's framing. The
CLO-660 description still asserted the wrong publish premise that the spec overturned.

Rule: until CLO-649 lands, arg.3 and arg.4 are short summaries written for the run. They
contain no `'`, `|`, `&`, `\` or newline, and they state the corrected premise when the
spec has overturned the ticket's own premise.

How to apply: write the summary from the spec's Problem Statement, not from the ticket.
Keep the verbatim ticket out of the argument list. The reviewer reads the spec file
itself.
