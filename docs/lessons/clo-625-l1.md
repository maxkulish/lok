# This repo has auto-merge off and branch-delete-on-merge off

`allow_auto_merge` is `false`, so `gh pr merge --auto` - the natural way to express "merge once CI
passes" - does nothing here. Any automation that waits for checks must poll `gh pr checks` itself,
and that poll must be bounded (`timeout` plus `--fail-fast`), because an unbounded `--watch` against
a stuck runner is a hang rather than a wait.

`delete_branch_on_merge` is also `false`, so `gh pr merge` needs an explicit `--delete-branch` or
branches accumulate on the remote.

Neither setting is visible from the code. Both were assumed-then-checked while writing CLO-625, and
either guess would have produced a command that failed on its first real run.
