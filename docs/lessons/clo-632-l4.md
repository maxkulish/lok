# TOML table keys can carry control characters; escape them before printing

The spec required that project-file values reach the terminal only escaped, and the
implementation printed no values. It did print the backend *name*, a TOML table key,
raw. A quoted TOML key holding a `` escape is valid and deserializes into the
`HashMap<String, BackendConfig>`, so the rejection error wrote an ANSI sequence to
stderr. The spec review, the implementation and the full test run all missed it.
Codex's pre-PR validation caught it.

Rule: treat table keys from an untrusted TOML file as untrusted text, same as values.
Format them with `str::escape_debug()`, which leaves ordinary names like `codex`
unchanged and escapes control characters.

How to apply: when an error names a config path built from file-supplied keys, add a
test whose key contains the ESC character and assert the error has none left raw, as
`project_backend_name_escaped_in_error` does.
