# A step skipped by `when` leaves no result, so unguarded references abort the workflow

When a step's `when` condition is false, the runner skips it and records
nothing. A later `{{ steps.<skipped>.output }}` is then an undefined value.
Interpolation errors propagate with `?` regardless of `continue_on_error` and
`min_deps_success = 0`, so the whole workflow stops at that step.
`design-review.toml` read `steps.claude_fallback` unguarded, which meant it could
never finish on the path where the Ollama review succeeded. That defect hid
behind the `${#OUTPUT}` parse failure until CLO-655 fixed it.

Rule: every reference to a step that has a `when` condition, or depends on one,
sits inside `{% if steps.X is defined %}...{% endif %}`.

How to apply: when adding `when` to a step, search the workflow for
`steps.<name>` and guard every hit. Test the skip path with stub shell steps
before any live run.
