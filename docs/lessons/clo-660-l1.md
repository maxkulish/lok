# Check who owns a crates.io name before reasoning about its publish history

Three sessions reasoned about the 28 published `lokomotiv` versions. The CLO-653 design
first called the crate "never published". CLO-654 and CLO-660 then "corrected" that to
"published, and the name is ours". Nobody queried the owners endpoint. The upstream
author `ducks` owns the name and published every version, all binary-only, and the last
one came out on the day of the last upstream commit. This repository has never
published, and it cannot publish `lokomotiv` without an owner grant. A version list says
only that a name is taken, not who took it.

Rule: a claim that this project has published or can publish a crate needs both
`/api/v1/crates/<name>/owners` and `published_by` from the versions API. In a
repository that began as a copy of another project, assume the registry name is
upstream's until those two say otherwise.

How to apply: run the two commands under "crates.io publishing" in
`docs/DEPENDENCIES.md` before any design that argues from publish state, such as
semver breaks, yanks, workspace splits or `rust-version`. A library publish from this
repository needs either an owner grant from `ducks` or a new crate name. That decision
is open and tracked in `docs/PROJECT.md` Up Next.
