# Re-running a report-writing workflow resurrects the problems you fixed in its output

The CLO-637 cycle hand-fixed `/Users/...` local-path leaks in
`docs/reviews/clo-637-codex-validation.md` (a Qodo finding), then re-ran the
pre-pr-validation workflow per its own one-bounded-iteration rule. The re-run
rewrote the report files from scratch and the leak came back; it was only
caught because the re-run finished before the branch merged.

Rule: a hand edit to a machine-written artifact lasts exactly until the next
run of its generator. When review feedback targets generated output, either fix
the generator in the same change, or re-apply the fix after every re-run and
say so in the PR - and diff-check generated files after any workflow re-run
that overlaps a review cycle.

How to apply: after re-running any `.lok` workflow that writes under
`docs/reviews/`, `git diff` those paths before pushing; if a finding was about
generated content, file the generator fix as its own issue immediately (here:
the pre-pr-validation prompt should demand repo-relative `path:line` refs).
