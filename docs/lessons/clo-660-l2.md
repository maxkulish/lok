# Compile documented examples as a downstream crate; doctests cannot see missing consumer dependencies

CLO-660 checked its new git dependency line by importing `create_backend` in a scratch
crate, and the check passed. Both documented quick starts still failed to compile
downstream, because they use `#[tokio::main]` and the snippet never declared `tokio`.
Repository doctests passed throughout, because this package already depends on tokio,
so the doctest build has it available. The user caught the gap in spec review.

Rule: a docs change whose snippet is a contract for consumers is verified by
extracting the documented dependency block and the example body verbatim into a
scratch binary crate, then running `cargo check` against the documented tag. An
import probe or a doctest does not count.

How to apply: reuse Script 7 from `specs/2026-09-15-clo-660-crate-ownership.md`. It
has an awk fence extractor for README code blocks and for `//!` rustdoc blocks. Add a
negative control once (remove a line the example needs and confirm the check fails),
so the probe is known to detect a missing dependency. A documented `cargo install`
command needs `--locked`, because `cargo install` otherwise ignores the package's
`Cargo.lock`.
