# `gh pr merge --delete-branch` drops the remote deletion when its local checkout fails

Merging from inside a worktree produces:

```
failed to run git: fatal: 'main' is already used by worktree at '<path>/lok'
```

The **merge succeeds** - `gh` reports `MERGED` - but `--delete-branch` first tries to switch the
local clone to the base branch, and when that fails it abandons the remote deletion too, without
failing the command. The branch is still on origin afterwards and nothing says so.

This repo is worked through worktrees, so the base branch being held by a sibling worktree is the
normal condition, not an edge case.

Remove the branch without touching local state:

```bash
gh api -X DELETE repos/{owner}/{repo}/git/refs/heads/<branch>
```

Any automation relying on `--delete-branch` should verify with
`git ls-remote --exit-code --heads origin <branch>` afterwards rather than assume. Tracked as
CLO-628.
