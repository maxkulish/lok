# Merge main into a multi-commit docs branch, and gate every scripted conflict resolution

CLO-660's branch had seven commits when main moved (#107, #108), and both sides had
edited `docs/PROJECT.md`. A rebase replays each commit, so the same aggregation-file
conflict came up more than once. A Python resolver asserted on a conflict-marker label
that did not match, exited without changing the file, and the chained
`; git add docs/PROJECT.md; git rebase --continue` still ran. The markers were committed
into the replayed spec commit before the next conflict stopped the rebase.
`git rebase --abort` restored the branch exactly.

Rule: lok squash-merges PRs, so a merge commit on the task branch never reaches main. For
a multi-commit branch whose conflicts are aggregation docs, `git merge origin/main` once
and resolve once, which also avoids a force-push. When a resolution is scripted, stage
nothing until a marker check passes, and join the steps with `&&`.

How to apply:
`if rg -q '^(<<<<<<<|=======|>>>>>>>)' <files>; then echo MARKERS_REMAIN; else git add <files> && git commit --no-edit; fi`.
Do not write it as `a && b || c && d`, because the commit then still runs when markers
are found.
When both sides remove different rows from the same table, keep both removals, and
combine both sides' `Last Updated` notes rather than picking one.
