# The Ollama leg's REVIEW_FAILED shows the Codex banner, not the cause

The Ollama review steps report failure as `REVIEW_FAILED: Empty or trivially
short output (stderr: <first 5 lines>)`. Those five lines are Codex startup text
such as "Reading additional input from stdin...". In CLO-655's live runs the
real cause was an Ollama cloud session usage-limit error at the end of the log.
The design-review and spec-review workflows also write stderr to fixed
`/tmp/lok-ollama-*.log` paths that the next run overwrites.

Rule: before retrying a failed Ollama review leg, read the whole stderr log for
that run. Treat a repeated empty output within seconds as quota or
authentication until the log says otherwise.

How to apply: copy `/tmp/lok-ollama-stderr.log` aside right after each live run
you need to diagnose, before starting the next one.
