# Check sibling worktrees and open PRs before starting a ticket

Two sessions fixed CLO-656 at the same time. The CLO-655 spec absorbed it, but that
decision existed only on the CLO-655 branch. `main`'s PROJECT.md still listed CLO-656
as Up Next and Linear still said Backlog. The second session wrote a spec, went
through two review rounds, implemented, validated and opened #100, all of which was
thrown away when #101 merged first. Only the field-name part survived, as #102.

Rule: aggregation files and Linear on `main` do not show what other in-flight branches
have claimed. Before initializing a workflow, look at live branches as well as `main`.

How to apply: at init, run `git worktree list`, `gh pr list --state open`, and
`git log --all --oneline --grep <ticket-id>`. If another branch or PR mentions the
ticket, message that session or ask the user before writing a spec.
