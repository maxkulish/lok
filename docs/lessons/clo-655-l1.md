# Assert diagnostics exactly, and probe them through the real call path

The test guarding `UnknownVariable` naming checked only that the reported
variable contained `missing`. It passed for months while every undefined
attribute path was reported as `'{{ .missing.output }}'`, with the `steps`
root dropped, because MiniJinja's error range covers `.missing.output` and not
the whole path. A range also points at a filter name when a filter receives an
undefined value, and past the end of input for an unclosed comment. None of this
was visible from MiniJinja's docs. A throwaway test module that called
`interpolate_with_fields` with the real `TemplateContext` exposed all three
in one run.

Rule: a test for an error message asserts the exact value it names, not a
substring. Before designing error mapping on top of a library's error metadata,
probe that metadata through lok's own call path with representative templates.

How to apply: add a temporary `#[cfg(test)]` probe module that prints kind,
range, sliced text and the mapped message for each case. Revert it after, and
turn the surprises into exact-match tests.
