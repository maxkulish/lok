# A file that records its own PR number needs two commits, not an amend

`gh pr create` needs a pushed branch, and the PR number does not exist until it returns. So a
workflow file that must contain its own PR URL cannot be written in one pass. The order is:

1. commit the content, push
2. `gh pr create`, capture number and URL
3. write them into the file, commit, push
4. **then** wait for CI

Amending step 1 instead requires a force-push and buys nothing - both shapes push twice, so CI runs
on the second push either way.

Waiting for CI after the second push rather than between 2 and 3 is the part worth keeping: it means
waiting once instead of twice, on the SHA that will actually be merged.

The same shape applies to anything self-referential in a PR - changelogs naming their own PR, status
files, release notes.
